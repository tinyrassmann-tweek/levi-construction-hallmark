Use the hosted version

  1. Open the landing page and explore the client demo. Demo changes stay in that browser and never enter the client database.
  2. Open the live workspace using the owner account. Create a project. Assigned client emails restrict server-side project access; team access is controlled by the ADMIN_EMAIL runtime setting.
  3. The landing page is public. Clients sign in with the email assigned to their project. Do not place real client records into a public demo.
  4. Read new leads in Lead inbox. Posts, messages, and concerns are saved in the portal. Email and SMS delivery are not configured.

Google Cloud launch

The included Cloud Run server uses Firestore for durable shared records, a dedicated service account, signed HttpOnly session cookies, a hashed team password, and random client project access codes. It does not use Cloud Run's temporary filesystem for records.

  1. Choose an existing Google Cloud project with billing approved for this venture. This task has not purchased services or enabled billing. Set LEVI_PROJECT_ID, LEVI_REGION (default us-east1), and LEVI_ADMIN_EMAIL in the terminal.
  2. Authenticate with gcloud. Enable Cloud Run, Cloud Build, Artifact Registry, Firestore, and Secret Manager in the chosen project.
  3. Create a Firestore Native database in the chosen region, if one does not already exist. Keep direct anonymous database access disabled.
  4. Create service account levi-web. Give it roles/datastore.user on this project. Create two Secret Manager secrets, levi-session-secret and levi-admin-password-hash. Grant this service account Secret Accessor only on those two secrets.
  5. Generate a random session secret (at least 32 characters) and place it directly in Secret Manager. Hash a chosen team password using google-cloud/hash-password.mjs via stdin in your private terminal; save the resulting salt:hash as the password-hash secret. Never commit secret values or put plaintext passwords into the app.
  6. Run bash google-cloud/deploy.sh from the source root. It deploys the source with a maximum of two instances and zero minimum instances. Google usage fees may still apply.
  7. Visit the returned run.app URL. Test consultation submission → team inbox. Create a test project and verify that a different client cannot access it.
  8. Team login uses LEVI_ADMIN_EMAIL and the chosen team password. In a project, click Client access code. Share it privately through your established channel. Client login uses the assigned email and code; code validity is 30 days and signed sessions expire after 8 hours. Creating a new code does not revoke old codes before expiry; revoke old access records and rotate the session secret when revocation is needed.
  9. Connect an owned domain using Firebase Hosting in front of the Cloud Run service, or another supported Google Cloud custom-domain option. Configure DNS only after the destination and record changes are selected. Domain changes have not been made.
